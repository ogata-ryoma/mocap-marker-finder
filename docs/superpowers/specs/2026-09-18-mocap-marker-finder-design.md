# mocap-marker-finder 設計書

作成日: 2026-09-18
状態: ユーザー承認済みの設計（grill-with-docs による Q1〜Q9 の合意を反映）

## 1. 目的と範囲

モーションキャプチャ用の再帰反射マーカーが迷子になったとき、iPhone のカメラで探すための静的 Web ページ。Vicon / OptiTrack のスタジオで、スタッフが迷子に気付いたその場で URL を開いて使う。

- 対象は**キャプチャボリューム外**の迷子マーカー。ボリューム内はキャプチャソフトの 3D ビューで拾えるので対象外
- 最難関ケースは **Vicon の指マーカー（3 mm 半球）**。これが見つかれば大きい物は自動的に見つかる
- 探索環境の最悪ケースは**明るい部屋**（照明を落とせない更衣室、廊下、機材置き場）
- やること: torch を点け、再帰反射で光る点を検出し、映像に赤丸と個数を重ねる
- やらないこと: 音、静止、方向案内、履歴、複数人共有、ネイティブアプリ化（ADR 0001 の退避条件を満たすまで）

用語は `docs/CONTEXT.md` に従う（再帰反射マーカー、迷子マーカー、キャプチャボリューム）。

## 3. 構成

### ファイル

```
/
├── index.html        画面の骨組み
├── style.css         見た目
├── app.js            画面の状態遷移、描画ループ、ログ、UI の配線
├── camera.js         getUserMedia、torch、ズーム、停止（ブラウザ専用。純関数部分だけ Node でテスト）
├── detect.js         純関数: しきい値化、連結成分、差分。DOM に触らない
├── blink.js          torch 点滅のスケジューラ。依存を注入するので Node でテストできる
├── scripts/serve.js  ローカル確認用の静的サーバー
├── test/
│   ├── detect.test.js
│   ├── blink.test.js
│   └── camera.test.js
├── package.json      "type": "module"。npm test = node --test
├── .nojekyll         GitHub Pages で Jekyll を通さない
├── README.md         使い方と対応機種
└── docs/
    ├── CONTEXT.md
    ├── adr/
    ├── verification.md   実機検証の記録
    └── superpowers/{specs,plans}/
```

- 外部ライブラリなし、ビルドなし。`index.html` を開けば動く
- `detect.js` は `ImageData` 相当の `{ data, width, height }` を受け取る純関数のみを持ち、ブラウザ API に依存しない。Node のテストで固める
- `blink.js` は torch の操作、フレーム取得、タイマーを引数で受け取る。Node のモックタイマーで点滅の順序を検証する
- 配信は GitHub Pages（`main` ブランチのルート）。URL は `https://ogata-ryoma.github.io/mocap-marker-finder/`

### 実行環境の前提

- iPhone の Safari。ホーム画面追加（PWA）はカメラ許可を毎回聞かれる既知の問題があるため、README では**ブックマークで開く**運用を案内する
- HTTPS 必須（カメラ API の条件）。GitHub Pages が満たす

## 4. 検出の流れ

1. `getUserMedia({ video: { facingMode: { ideal: 'environment' }, width: { ideal: 1280 }, height: { ideal: 720 } } })` で背面カメラを取得
2. トラックの `getCapabilities()` を読み、torch が無ければ非対応画面へ（5 章）
3. `applyConstraints({ advanced: [{ torch: true }] })` で点灯。失敗したら非対応画面へ
4. `requestAnimationFrame` ごとに映像を幅 480 px（高さは比率維持）の作業キャンバスへ縮小描画し、`ImageData` を取る
5. モードに応じて 2 値マスクを作る
   - **通常モード**: 画素の輝度 `max(R, G, B)` がしきい値以上なら 1
   - **差分モード**: torch を点灯と消灯で交互に切り替え、切り替えの完了から 260 ms 待ってフレームを取る（1 周期は約 600 ms）。「点灯フレーム」と「消灯フレーム」の輝度差 `max(0, on - off)` がしきい値以上なら 1。差分画像は半周期ごとに更新し、その間の描画には最新の差分画像を使う
6. マスクに 4 近傍の連結成分ラベリングをかけ、面積が最小面積未満の塊を捨てる
7. 残った塊を面積の降順に並べ、上位 50 個に赤丸（半径は `max(8, sqrt(面積) × 1.6)` px）と面積を描き、個数を HUD に出す
8. `getCapabilities().zoom` があればズームスライダーを出し、`applyConstraints({ advanced: [{ zoom }] })` で反映

しきい値の初期値は通常 235、差分 80、最小面積 2 px。いずれもスライダーで変えられる。

## 5. 端末の判定（非対応画面）

- 判定は**カメラ許可の後**に行う。`getSupportedConstraints().torch` はブラウザが制約を知っているかを返すだけで、LED の無い iPad でも true になり得るため使わない
- 判定は torch の点灯を試みてから行う。条件は「点灯の `applyConstraints` が失敗」または「成功しても capabilities に torch が無く、`getSettings().torch` も true にならない」のどちらか。capabilities の torch の表現（boolean か配列か）は端末により違い得るので両方を受け付ける
- 非対応画面では、端末名（`track.label`）と理由を表示し、カメラを停止して終了する。輝度しきい値モードだけで続行する救済はしない（Q7 = A）
- iOS の版番号による判定はしない。torch が Safari に入った版を確定できていないため、実行時の判定を唯一の門にする
- 開発用の例外として、URL に `?skipTorch` を付けると torch の門を飛ばして検出ループに入れる（PC のブラウザで偽カメラを使って動作を見るため）。ログに赤字で明示し、README には書かない

## 6. 画面

状態は 3 つ。

- **待機**: 説明文と「開始」ボタン。ログ欄
- **検出中**: 映像（赤丸と個数の HUD 付き）、スライダー 3 本（しきい値、最小面積、ズーム。ズームは対応時のみ）、差分モードの切替、「停止」ボタン、ログ欄
- **非対応**: 端末名と理由、README へのリンク

振る舞い:

- 「開始」で許可要求、torch 自動点灯、検出開始まで一気に進む
- 「停止」、ページの非表示（`visibilitychange`）、タブを閉じるときは torch を消してトラックを止める
- すべてのエラーと主要な状態変化は画面内のログ欄に時刻付きで出す（iPhone には devtools が無い）
- UI は日本語のみ

## 7. エラー処理

| 事象 | 扱い |
|---|---|
| `NotAllowedError`（許可拒否） | 待機画面に「設定 > Safari > カメラ で許可してください」と表示 |
| `NotFoundError`（カメラ無し） | 非対応画面 |
| torch 点灯失敗、または点灯後も capabilities と settings のどちらにも torch が出ない | 非対応画面 |
| zoom の `applyConstraints` 失敗 | ログに出してズームスライダーを隠す。検出は続行 |
| 差分モード中の torch 切替失敗 | ログに出して通常モードへ戻す |
| 想定外の例外（`error` / `unhandledrejection`） | ログに出す。検出ループは止めない |

## 8. テスト

### 自動テスト（`node --test`）

`detect.js` の純関数を合成フレームで検証する。

- 1 つの明るい塊 → 塊 1 個、重心と面積が正しい
- 離れた 2 つの塊 → 2 個、面積の降順
- 斜めに接する画素 → 4 近傍なので別の塊として数える
- 最小面積未満の塊 → 捨てられる
- 画像の端に接する塊 → 端で止まり、隣の行に漏れない
- 差分: 点灯・消灯の両フレームから `max(0, on - off)` が正しく出る。消灯側が明るい画素は 0 になる

### 実機検証（手順は README に書く）

1. 明るい部屋で 3 mm 半球を床に置く
2. 1〜3 m 離れ、立った高さから「開始」
3. 通常モードで赤丸が付くか。付かなければ差分モードで付くか
4. 差分モードの表示で、背景が暗いままか、全体が明るく持ち上がるかを記録する（9 章のリスク）

結果は日付、端末、iOS の版とともに `docs/verification.md` に残す。

## 9. 合格ラインとリスク

**合格ライン**: 明るい部屋で、3 mm 半球を 2 m 離れた立った高さから、通常か差分どちらかのモードで赤丸が付くこと。満たさなければ ADR 0001 の条件でネイティブ移行を判断する。

**未検証のリスク**:

- **差分モードと自動露出**: torch を点滅させると iOS の自動露出が点灯と消灯の間で動き、差分に「画面全体の明るさのずれ」が乗る可能性がある。スタジオでの spike で最初に確かめる点。持ち上がる場合はフレームごとの正規化（差分の中央値を引く）を足し、それでも駄目ならネイティブへ
- **2 m 先の 3 mm**: 幅 480 px の作業画像では数ピクセルになる。ズームで補えるかは実機で見る
- **torch の発熱と電池**: 連続点灯は端末が熱くなる。長時間の探索では停止を挟む運用にする（README に書く）

**検証済み**: iOS Safari から torch を点灯できること（2026-09-18、ユーザーの iPhone で確認）。zoom は WebKit のソースで対応を確認しただけで、実機では未確認。

## 11. 実装の順序（概要）

1. `detect.js` を TDD で書く（合成フレームのテストが先）
2. `index.html` / `style.css` / `app.js` を組み、手元の PC のブラウザで状態遷移とログを確認
3. 非公開リポジトリを作って push、Pages を有効化して公開へ切り替え
4. ユーザーの iPhone で待機 → 検出中 → 停止の流れと torch を確認
5. スタジオで 3 mm 半球の実機検証（合格ラインと差分モードのリスクを確認）
6. 結果に応じて差分モードの正規化を足すか、ADR 0001 の退避を判断する

詳細な手順は実装計画（writing-plans）で切る。
